# 书签库多选 UX 规格：Selection Mode

版本：0.1  
日期：2026-05-23  
适用范围：Library / 书签库中的网格、列表、域名结果视图

---

## 1. 结论

多选不应该依赖用户去点很小的 checkbox。

优化后的多选应该像文件管理器一样：

```text
进入选择模式
→ 点击卡片/行主体即可选中
→ 支持 Shift 连选
→ 支持方向键移动焦点
→ 支持 Shift + 方向键扩展选择
→ 支持框选
→ Selection Bar 显示当前选择范围和可执行动作
```

checkbox 保留，但只是状态标记和精确点击点，不是主要选择方式。

---

## 2. 核心对象

### 2.1 Scope

当前书签库结果范围。

示例：

```text
搜索 react + 分类 技术/前端 + 标签 性能
```

### 2.2 Focus

当前键盘焦点所在的书签项。

```ts
focusId: string | null
```

### 2.3 Anchor

范围选择的起点。Shift 选择时从 anchor 扩展到 focus。

```ts
anchorId: string | null
```

### 2.4 Selection

当前已选择的书签集合。

```ts
selectedIds: Set<string>
```

### 2.5 Selection Scope

Selection Scope 是当前操作真正影响的对象：

```text
Selection Scope = 当前 Scope ∩ selectedIds
```

任何批量操作必须基于 Selection Scope，而不是全库。

---

## 3. 进入与退出选择模式

### 3.1 进入方式

用户可以通过以下方式进入选择模式：

- 点击工具栏“选择”。
- 长按某张卡片/某行。
- 使用快捷键 `Space` 在当前焦点项上开始选择。
- 右键打开菜单后选择“选择此项”。

### 3.2 退出方式

- `Esc`：如果有选中项，先清除选择；如果没有选中项，退出选择模式。
- 点击 Selection Bar 的“清除”。
- 点击 Selection Bar 的“完成”或关闭按钮。

---

## 4. 鼠标选择

### 4.1 卡片/行主体选择

进入选择模式后：

| 动作 | 结果 |
|---|---|
| 点击卡片/行空白区域 | 选中 / 取消选中 |
| 点击 checkbox | 选中 / 取消选中 |
| 点击标题、域名、打开图标 | 打开书签，不触发选择 |
| Shift + 点击 | 从 anchor 到当前项连续选择 |
| Ctrl/Cmd + 点击 | 追加或移除当前项，不清除其他选择 |

要求：

- 可点击区域不能只有 checkbox。
- 卡片/行进入选择模式后，应有清晰 hover 和 selected 状态。
- checkbox 放在卡片左上或列表行左侧，作为状态提示。

### 4.2 框选

网格视图必须支持框选。

交互：

```text
按住空白处拖拽
→ 出现选择框
→ 框选区域覆盖到的卡片被选中
```

规则：

- 从结果区域空白处开始拖拽才触发框选。
- 从卡片内部拖拽默认不触发框选，避免和拖拽排序/打开冲突。
- 按住 Ctrl/Cmd 框选：追加到已有选择。
- 不按 Ctrl/Cmd 框选：替换当前选择。

列表视图可先不做框选，优先支持 Shift 连选和 Shift + 方向键。

## 5. 键盘选择

### 5.1 基础快捷键

| 快捷键 | 行为 |
|---|---|
| `Arrow Up` | 焦点移动到上一个可见项 |
| `Arrow Down` | 焦点移动到下一个可见项 |
| `Arrow Left` | 焦点移动到左侧卡片/上一项 |
| `Arrow Right` | 焦点移动到右侧卡片/下一项 |
| `Space` | 切换当前焦点项选中状态 |
| `Shift + Space` | 从 anchor 到 focus 扩展选择 |
| `Shift + Arrow` | 移动焦点并扩展选择 |
| `Ctrl/Cmd + A` | 选择当前 Scope 的全部结果 |
| `Esc` | 清除选择或退出选择模式 |
| `Enter` | 打开当前焦点书签 |
| `Ctrl/Cmd + Enter` | 新标签打开当前焦点书签 |

### 5.2 Shift + 方向键

必须支持。

行为：

```text
第一次 Shift + Arrow：
  如果 anchorId 为空，则 anchorId = 当前 focusId
  焦点移动到目标项
  选中 anchor 到新 focus 的范围

继续 Shift + Arrow：
  anchorId 不变
  focusId 继续移动
  selection 更新为 anchor 到 focus 的范围
```

### 5.3 网格视图方向键规则

网格视图中：

- `Left/Right`：同一行左右移动。
- `Up/Down`：移动到上一行/下一行相同列。
- 如果目标列不存在，移动到该行最后一个可见项。

`Shift + 方向键` 的选择范围建议先采用“结果顺序连续范围”，不要做矩形范围。

原因：

- 虚拟列表和响应式网格下，矩形范围容易因列数变化产生不稳定结果。
- 连续范围更符合 DOM/数据顺序，也更容易实现和解释。

### 5.4 列表视图方向键规则

列表视图中：

- `Up/Down`：移动焦点。
- `Shift + Up/Down`：扩展连续选择。
- `Left/Right`：仍然移动焦点，分别等价于上一项/下一项。
- `Shift + Left/Right`：仍然扩展选择，分别等价于向上一项/下一项扩展。

不要把 `Left/Right` 分配给展开详情、打开侧栏、切换面板等动作。  
在书签结果区，只要焦点在卡片/行上，四个方向键都用于移动结果项焦点。这样网格和列表拥有一致的键盘模型。

## 6. Selection Bar

进入选择模式后显示 Selection Bar。

### 6.1 空选择

```text
已选 0 / 当前结果 84
[全选当前结果] [退出选择]
```

### 6.2 有选择

```text
已选 12 / 当前结果 84
当前范围：搜索 react · 分类 技术/前端 · 标签 性能

[AI 归档所选] [补缩略图] [更新截图] [归档/恢复] [删除] [更多]
[反选] [清除]
```

### 6.3 当前可见 vs 当前筛选全部

如果结果使用虚拟列表或分页，必须区分：

```text
已选择当前可见 50 条
[选择当前筛选全部 842 条]
```

点击“选择当前筛选全部”后：

```text
已选择当前筛选结果全部 842 条
范围：搜索 react · 分类 技术/前端
```

不能让用户误以为只选择了当前屏幕，也不能让用户误以为选择了全库。

## 7. 批量动作确认

中高风险操作必须显示 Selection Scope。

### 7.1 删除确认

```text
将删除 84 条书签

范围：
搜索 react
分类 技术/前端
标签 性能

可撤销：否

[取消] [确认删除]
```

### 7.2 AI 归档确认

```text
将对 84 条书签执行 AI 归档

将修改：
- 分类
- 标签
- 摘要
- 归档状态

将跳过：
- 已归档 12 条
- 失效链接 3 条

[取消] [预览队列]
```

## 8. 视觉状态

### 8.1 普通状态

卡片/行正常显示，不显示强 checkbox。  
hover 时可显示轻量 checkbox 或更多操作。

### 8.2 选择模式

所有可选项显示 checkbox。  
卡片/行主体可点击选择。  
当前 focus 项显示清晰 focus ring。  
已选项显示 selected 背景和边框。

### 8.3 键盘焦点

焦点不能只依赖浏览器默认 outline。  
需要产品内一致样式：

```text
2px primary ring + 轻微背景变化
```

## 9. 实现优先级

### P0

1. 增加选择模式。
2. 卡片/行主体可点击选择。
3. Selection Bar 显示已选数量和当前 Scope。
4. `Esc` 清除/退出。
5. `Ctrl/Cmd + A` 选择当前 Scope。

### P1

1. `focusId` / `anchorId` 状态。
2. 方向键移动焦点。
3. `Shift + Arrow` 扩展选择。
4. `Space` 切换当前焦点项。
5. `Shift + 点击` 连选。

### P2

1. 网格框选。
2. 当前可见 vs 当前筛选全部二段式选择。
3. 批量动作统一确认面板。

### P3

1. 移动端长按进入选择。
2. 触控下的底部 Selection Bar。
3. 键盘快捷键帮助提示。

---

## 10. 验收标准

1. 用户不用瞄准 checkbox，也能通过点击卡片主体完成多选。
2. 网格视图支持键盘上下左右移动焦点。
3. `Shift + Arrow` 可以连续扩展选择。
4. `Ctrl/Cmd + A` 选择的是当前 Scope，不是全库，界面明确说明。
5. 用户能区分“当前可见 50 条”和“当前筛选全部 842 条”。
6. 删除、AI 归档等批量操作前能看到 Selection Scope。

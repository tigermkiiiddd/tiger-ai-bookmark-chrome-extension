# TIGERMARKIII 交互路径与布局重构设计文档

版本：0.1  
日期：2026-05-23  
状态：设计草案  
读者：产品、设计、前端实现

---

## 1. 文档目标

本文件从第一性原理重新梳理 TIGERMARKIII 的交互路径和布局结构，目标不是增加新功能，而是让已有能力变得更容易理解、更少打断、更可控。

当前产品已经具备较完整的能力：收藏、搜索、筛选、标签/分类、AI 归档、失效检测、同步、备份、标签工作台等。主要问题不在“有没有功能”，而在：

- 用户不知道下一步应该去哪里。
- 日常浏览和重型整理混在同一个页面头部。
- 侧栏同时承担导航、筛选、分类管理、标签入口，职责过多。
- AI 能力很多，但“快速整理”和“结构治理”的边界不清。
- 批量操作、维护操作、危险操作的确认方式不统一。
- 页面布局密度和信息层级不稳定，导致用户需要反复扫描。

本设计文档给出一套目标信息架构、页面布局规则、核心流程和落地优先级。

## 2. 第一性原理

### 2.1 用户真正要完成的工作

书签管理不是“保存 URL”，而是管理个人知识资产。用户的核心任务只有五类：

1. 收进来：把当前页快速保存，并尽量少填字段。
2. 找得到：按记忆线索快速定位收藏。
3. 看得懂：看到一个条目时能判断它是什么、是否还有用。
4. 理得清：分类和标签不要无限碎裂，结构要可维护。
5. 管得住：失效、重复、过期、同步冲突都能被发现和处理。

所有页面和操作都应该服务这五类任务。

### 2.2 产品心智

TIGERMARKIII 应该被用户理解为：

> 一个带 AI 的 Chrome 书签工作台，用来收藏、查找、整理和维护书签。

不应该被理解为：

- 一个普通网页后台。
- 一个聊天工具。
- 一个文件夹/标签编辑器集合。
- 一个会静默替用户大改数据的自动化工具。

### 2.3 设计原则

1. 日常任务优先：默认界面应该优先服务“找书签、打开书签、轻量编辑”。
2. 重型任务隔离：AI 批量归档、标签治理、失效检测、同步应进入明确工作台。
3. 状态先于动作：在批量操作前，先让用户看清范围、数量、风险和可撤销性。
4. 导航和筛选分离：导航回答“我在哪个工作区”，筛选回答“我看哪些数据”。
5. 单页只保留一个主任务：每个页面要有清晰的主操作，不堆满同级按钮。
6. AI 操作必须可解释：AI 做了什么、准备做什么、哪些会落库、能否撤销，要可见。
7. 危险操作一致：删除、清空、批量修改、同步覆盖等都走统一确认模式。
8. 扩展环境优先：设计验收以 Chrome Extension 运行环境为准，不以普通浏览器直开为准。

## 3. 当前结构诊断

### 3.1 当前页面与入口

现有主要路由：

| 路由 | 当前含义 | 问题 |
|---|---|---|
| `/` | 全部书签 / 筛选结果 / 三种视图 | 主页承载过多操作按钮 |
| `/settings` | 设置中心 | 内容长，分组可继续拆清 |
| `/search` | 搜索结果 | 与主页筛选结果心智重叠 |
| `/category/:categoryName` | 分类页 | 与侧栏分类筛选关系不够清楚 |
| `/tag/:tagName` | 标签页 | 与侧栏标签筛选关系不够清楚 |
| `/link-check` | 链接检测流程 | 入口藏在主页按钮 |
| `/broken-links` | 失效链接处理 | 与 link-check 是同一维护域，应整合心智 |
| `/ai-archive` | AI 批量归档工作台 | 是重型流程，入口应更明确 |
| `/dedup` | 去重分析 | 是维护流程，当前和主页按钮同级 |
| `/tag-workbench` | 标签/分类优化工作台 | 是结构治理流程，当前文案和入口仍偏功能按钮 |
| `/graveyard` | URL 坟场 | 属于维护/历史记录，不应只放头部 icon |

### 3.2 当前布局问题

Header 当前包含：侧栏开关、品牌、添加书签、坟场、主题、设置、头像。  
MainPageHeader 当前包含：标签工作台、选中项批量操作、批量 AI 归档、批量截图、失效检测、去重分析。  
Sidebar 当前包含：搜索、清除筛选、全部书签、状态筛选、分类树、标签列表、添加分类。

结果是：

- 顶部操作太多，用户不容易区分“全局操作”和“当前列表操作”。
- 主页按钮承担了太多“跳转到工作台”的职责。
- 侧栏既像导航，又像筛选器，又像分类管理器。
- 选中态的批量操作和全局批量操作混在同一行。
- 维护型任务没有统一入口。

## 4. 目标信息架构

建议把产品拆成 5 个顶层工作区：

1. 书签库
2. 整理工作台
3. 健康维护
4. 同步与备份
5. 设置

### 4.1 顶层导航

| 顶层工作区 | 目标用户问题 | 包含能力 |
|---|---|---|
| 书签库 | 我要找、看、打开、轻量编辑书签 | 全部书签、搜索、筛选、分类/标签浏览、网格/列表/域名视图 |
| 整理工作台 | 我要把收藏结构整理好 | AI 归档、标签/分类治理、重复整理、批量补图 |
| 健康维护 | 我要清理坏链接、过期内容、坟场记录 | 链接检测、失效链接、URL 坟场、恢复/删除 |
| 同步与备份 | 我要和 Chrome 书签互通，或备份数据 | Chrome 导入、导出、同步、JSON 备份/恢复 |
| 设置 | 我要配置 AI、主题、策略和安全项 | API、模型、内容安全、主题、检测策略 |

### 4.2 推荐路由

短期可以保留当前路由，只调整入口和页面标题。中期建议将路由语义统一：

| 目标路由 | 页面 | 兼容现有 |
|---|---|---|
| `/library` 或 `/` | 书签库 | 现有 `/` |
| `/organize` | 整理总览 | 新增聚合页 |
| `/organize/ai-archive` | AI 归档 | 现有 `/ai-archive` |
| `/organize/tags` | 标签/分类治理 | 现有 `/tag-workbench` |
| `/organize/dedup` | 去重分析 | 现有 `/dedup` |
| `/maintenance` | 健康维护总览 | 新增聚合页 |
| `/maintenance/link-check` | 链接检测 | 现有 `/link-check` |
| `/maintenance/broken-links` | 失效链接处理 | 现有 `/broken-links` |
| `/maintenance/graveyard` | URL 坟场 | 现有 `/graveyard` |
| `/sync` | 同步与备份 | 可从 settings 中拆出 |
| `/settings` | 设置 | 保留 |

## 5. 全局布局设计

### 5.1 Shell 布局

目标结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ App Bar: 品牌 / 当前工作区 / 全局搜索 / 添加 / 设置 / 主题       │
├───────────────┬──────────────────────────────────────────────┤
│ Primary Nav   │ Page Header: 标题 / 范围 / 主操作               │
│               ├──────────────────────────────────────────────┤
│ Context Panel │ Toolbar: 视图、排序、筛选、选择态操作             │
│               ├──────────────────────────────────────────────┤
│               │ Content: 列表、工作台、队列、详情面板             │
└───────────────┴──────────────────────────────────────────────┘
```

### 5.2 App Bar 职责

只放全局、跨页面稳定的东西：

- 侧栏开关。
- 品牌。
- 当前工作区名称。
- 全局添加书签。
- 主题切换。
- 设置入口。

不放：

- 去重分析。
- 链接检测。
- 批量 AI 归档。
- 标签优化。
- URL 坟场。

这些都不是全局常驻操作，而是工作区任务。

### 5.3 左侧栏职责

左侧栏拆成两层：

第一层：主导航。

- 书签库
- 整理工作台
- 健康维护
- 同步与备份
- 设置

第二层：当前工作区上下文。

当处于书签库：

- 状态筛选
- 分类树
- 标签列表

当处于整理工作台：

- AI 归档
- 标签/分类治理
- 去重分析
- 批量截图

当处于健康维护：

- 链接检测
- 失效链接
- URL 坟场

这样侧栏不再同时扮演所有角色。

## 6. 书签库页面设计

### 6.1 页面目标

书签库是默认首页，目标是“找得到、看得懂、能轻量操作”。它不是所有批量工具的入口集合。

### 6.2 页面结构

```text
Page Header
- 标题：书签库 / 筛选结果
- 副标题：总数、当前范围、筛选数
- 主操作：添加书签

Query Bar
- 搜索输入
- 当前筛选 chips
- 清除筛选

Toolbar
- 视图切换：网格 / 列表 / 域名
- 排序：创建时间 / 更新时间 / 标题 / 分类
- 排序方向
- 选择模式入口

Selection Bar
- 已选数量
- AI 归档所选
- 补缩略图
- 更新截图
- 归档/恢复
- 删除

Content
- 网格卡片 / 列表 / 域名分组
```

### 6.3 关键改动

1. 从主页头部移除“批量 AI 归档、批量更新截图、检查失效链接、去重分析”等重型按钮。
2. 保留轻量动作：添加、搜索、筛选、排序、视图切换。
3. 只有用户进入选择态后，才显示批量操作。
4. 将右键菜单保留为效率入口，但界面上必须有可见的选择操作，不能依赖用户发现右键。
5. “域名视图”应属于视图模式，不应改变可用操作太多；如果有操作差异，要明确说明。

### 6.4 书签卡片信息层级

卡片从上到下：

1. 缩略图或站点图标。
2. 标题。
3. 域名。
4. 摘要或备注一行。
5. 分类路径。
6. 标签前 3-5 个。
7. 状态、时间、AI 归档状态。
8. 更多操作。

卡片不应承载过多按钮。常用动作通过点击/双击/更多菜单进入。

## 7. 整理工作台设计

### 7.1 工作台目标

整理工作台处理“结构会被改变”的任务。它需要比书签库更强调：

- 范围确认。
- 预览。
- 可暂停。
- 可撤销。
- 执行结果。

### 7.2 整理工作台首页

新增一个整理总览页，展示四张任务入口：

| 任务 | 适合场景 | 风险等级 | 入口文案 |
|---|---|---|---|
| AI 批量归档 | 未整理书签很多，需要补分类/标签/摘要 | 中 | 整理未归档书签 |
| 标签/分类治理 | 标签过碎、分类混乱、需要合并/移动 | 高 | 治理标签和分类 |
| 去重分析 | 重复收藏或近似重复很多 | 中 | 查找重复书签 |
| 批量补图 | 卡片缺缩略图，想提升浏览识别 | 低 | 批量补缩略图 |

每个入口要显示：

- 将影响哪些数据。
- 是否会直接落库。
- 是否支持撤销或暂停。
- 上次执行时间。

### 7.3 AI 归档流程

推荐流程：

1. 选择范围：全部 / 当前筛选 / 所选 / 未归档。
2. 预检：排除失效、已归档、已完整分析的书签。
3. 队列预览：显示将处理数量、预计耗时、失败风险。
4. 执行：开始 / 暂停 / 继续 / 停止。
5. 结果：成功、失败、跳过、可重试项。
6. 后续：查看结果、处理失败、回到书签库。

页面布局：

```text
Header: AI 归档 / 范围 / 状态
Progress Strip: 进度、速度、剩余时间
Control Bar: 开始、暂停、继续、停止
Queue Grid/List: 当前处理项、成功、失败、跳过
Result Summary: 完成后展示
```

### 7.4 标签/分类治理流程

当前 `TagWorkbenchPage` 已有三个视图：AI 助手、标签树、AI 分类建议。建议重新定义为：

1. 结构总览：标签云 + 统计 + 风险提示。
2. 标签树：精确管理。
3. AI 建议：合并、移动、重命名、删除的建议列表。
4. 审批记录：已执行/待确认/已撤销。

`Agent` 不应被设计成“聊天页优先”，而应是“结构治理工作台里的智能助手面板”。聊天只是输入方式，核心对象是变更建议。

标签云规则：

- Home 按钮固定在视图区右上。
- 缩放、平移、选择、展开/折叠要有一致反馈。
- 节点大小表达使用量，不表达层级。
- 层级关系用连线和详情面板表达。
- 选择标签后，右侧详情面板显示路径、书签数、子标签数、常用书签、可执行动作。

AI 建议规则：

- AI 只生成建议，不应无提示直接落库。
- 建议必须按风险分组：低风险重命名、中风险移动、高风险合并/删除。
- 每条建议显示“原因、影响数量、可撤销性”。
- 批量应用前给出变更摘要。

### 7.5 去重分析

去重不应只是一个孤立页面。它属于整理工作台，应使用相同的模式：

1. 扫描范围。
2. 生成重复组。
3. 用户逐组确认。
4. 批量应用。
5. 结果回顾。

## 8. 健康维护设计

### 8.1 工作区目标

健康维护回答：哪些书签坏了、哪些需要清理、哪些可以恢复。

### 8.2 页面组成

健康维护总览包含：

- 链接检测状态：上次检查时间、待检查数量、跳过策略。
- 失效链接摘要：站点失效、页面失效、未知失效。
- URL 坟场：最近删除/归档/失效记录。
- 建议操作：开始检测、处理站点失效、查看坟场。

### 8.3 链接检测流程

流程：

1. 选择范围：全部 / 当前筛选 / 未检测 / 距上次检测超过 N 天。
2. 预估数量。
3. 执行检测。
4. 结果分类：可访问、站点失效、页面失效、超时、跳过。
5. 进入失效链接处理。

### 8.4 失效链接处理

失效处理不应只有“删除”。应提供四类动作：

- 打开确认。
- 修改 URL。
- 恢复为正常。
- 删除。

站点失效可以按域名聚合，提供批量删除，但必须强确认。

## 9. 同步与备份设计

### 9.1 从设置中拆出同步

Chrome 同步和 JSON 备份是高风险数据操作，不应该埋在普通设置页中。建议独立为“同步与备份”工作区。

### 9.2 页面结构

```text
Sync Overview
- 当前同步状态
- 最近同步时间
- 同步方向
- 冲突策略

Chrome Interop
- 从 Chrome 导入
- 导出到 Chrome
- 双向同步

Backup
- 导出 TIGERMARKIII 数据
- 导入备份
- 清空数据
```

### 9.3 风险分级

| 操作 | 风险 | 交互要求 |
|---|---|---|
| 导出备份 | 低 | 一次点击即可 |
| 从 Chrome 导入 | 中 | 需要预览数量和冲突策略 |
| 导出到 Chrome | 中 | 需要确认目标文件夹 |
| 双向同步 | 高 | 需要显示方向、冲突策略、预估影响 |
| 清空数据 | 极高 | 双确认，最好要求输入确认词 |

## 10. 设置页设计

设置页只保留“产品行为偏好”，不承载任务流程。

建议分组：

1. AI 配置
   - API Key
   - Base URL
   - 模型
   - 内容安全等级
   - 自动标签/自动分析开关

2. 显示与主题
   - 主题
   - 默认视图
   - 每页/加载策略

3. 链接检测策略
   - 跳过周期
   - 超时设置
   - 检测方式说明

4. 高级
   - 重置归档状态
   - 清空数据入口跳转到同步与备份危险区

## 11. Popup 设计原则

Popup 是“当前页快速收藏/更新”的地方，不应变成完整管理后台。

Popup 只做：

- 识别当前页。
- 显示是否已收藏。
- 添加或更新当前页。
- 可选 AI 分析当前页。
- 快速选择分类/标签。
- 跳转到完整工作台。

Popup 不做：

- 全量书签浏览。
- 大批量整理。
- 标签结构治理。
- 同步和维护。

## 12. 状态、反馈与确认规范

### 12.1 操作状态

所有长任务统一四态：

- idle：尚未开始。
- running：执行中。
- paused：已暂停。
- completed：已完成。
- failed：整体失败。

单条任务统一五态：

- pending
- processing
- success
- skipped
- failed

### 12.2 反馈位置

- 页面内长任务：使用顶部进度区，不用 alert。
- 单条错误：显示在对应条目上。
- 全局错误：显示在 App Shell 顶部。
- 成功反馈：短 toast 或页面结果摘要。
- 危险确认：使用专门确认对话框，不用浏览器 `confirm` 作为最终形态。

### 12.3 确认分级

| 等级 | 示例 | 确认方式 |
|---|---|---|
| 低 | 切换视图、排序 | 无确认 |
| 中 | 批量 AI 归档、批量截图 | 范围预览 + 开始 |
| 高 | 合并标签、删除失效域名 | 影响摘要 + 明确确认 |
| 极高 | 清空全部数据、覆盖同步 | 双确认 / 输入确认词 |

## 13. 具体落地优先级

### P0：先清心智，不大改架构

1. Header 只保留全局操作。
2. MainPageHeader 移除重型任务按钮，放入“整理工作台/健康维护”的入口。
3. 选择态批量操作改成独立 Selection Bar。
4. 侧栏顶部增加主导航分组。
5. 统一页面标题和返回路径文案。
6. 将 `alert/confirm` 使用点列出，逐步替换为统一对话框。

### P1：建立工作区

1. 新增整理工作台总览页。
2. 新增健康维护总览页。
3. 将去重、AI 归档、标签治理归入整理工作台。
4. 将链接检测、失效链接、坟场归入健康维护。
5. 将 Chrome 同步和备份从设置中拆出。

### P2：提升复杂流程可信度

1. AI 建议改为“建议列表 + 审批记录”优先，聊天降为辅助入口。
2. 所有批量任务增加范围预检。
3. 所有高风险任务增加影响摘要。
4. 建立统一撤销/回滚边界说明。

### P3：细节体验

1. 键盘快捷键和焦点管理。
2. 空状态和错误状态统一。
3. 响应式布局规则细化。
4. 视觉密度统一：工具栏、卡片、表格、详情面板采用同一间距体系。

## 14. 页面布局细则

### 14.1 标题规则

每页只能有一个 H1。H1 表示用户当前工作区，不使用营销话术。

示例：

- 书签库
- AI 归档
- 标签与分类治理
- 链接健康
- 同步与备份
- 设置

### 14.2 主操作规则

每页最多一个主按钮。多个同级按钮会降低决策速度。

示例：

- 书签库：添加书签。
- AI 归档：开始归档。
- 链接检测：开始检测。
- 同步与备份：根据当前 tab 显示导入/同步/导出。

### 14.3 工具栏规则

工具栏只放“改变当前列表呈现方式”的控件：

- 视图切换。
- 排序。
- 筛选。
- 选择模式。

不放跨工作区跳转。

### 14.4 详情面板规则

复杂对象使用右侧详情面板：

- 标签详情。
- 分类详情。
- 书签详情。
- 失效链接详情。
- AI 建议详情。

详情面板内的操作只影响当前对象，不做全局批量动作。

### 14.5 移动端规则

移动端采用：

- 顶部 App Bar。
- 主导航抽屉。
- 详情面板变成底部 sheet。
- 批量操作变成底部 action bar。
- 不在移动端强行显示三栏布局。

## 15. 推荐的用户路径

### 15.1 新用户第一次使用

1. 安装扩展。
2. 打开当前页 Popup。
3. 保存当前页。
4. 进入书签库查看。
5. 设置 AI Key。
6. 从 Chrome 导入已有书签。
7. 运行一次 AI 归档或标签治理。

### 15.2 日常收藏

1. 用户浏览网页。
2. 点击扩展 Popup。
3. 添加/更新书签。
4. AI 可选分析。
5. 用户继续浏览，不进入完整后台。

### 15.3 找资料

1. 打开书签库。
2. 搜索关键词。
3. 用分类/标签/状态缩小范围。
4. 切换网格/列表/域名视图。
5. 打开目标书签。

### 15.4 大整理

1. 进入整理工作台。
2. 选择任务：AI 归档 / 标签治理 / 去重。
3. 选择范围。
4. 预览影响。
5. 执行。
6. 查看结果。
7. 回到书签库验证结构。

### 15.5 健康清理

1. 进入健康维护。
2. 运行链接检测。
3. 查看失效分组。
4. 对站点失效批量处理。
5. 对页面失效逐条修复或删除。

## 16. 验收标准

### 16.1 可理解性

新用户应能在 30 秒内说清：

- 保存当前页去 Popup。
- 找书签去书签库。
- 大规模整理去整理工作台。
- 坏链接去健康维护。
- Chrome 导入/备份去同步与备份。
- API Key 和偏好去设置。

### 16.2 操作路径

常用任务目标路径：

| 任务 | 目标点击深度 |
|---|---|
| 添加当前页 | 1 次：扩展图标 |
| 搜索书签 | 1 次：书签库搜索 |
| 打开书签 | 1-2 次 |
| 批量整理所选 | 选择后 1 次 |
| AI 整理全部 | 2-3 次，必须经过范围确认 |
| 链接检测 | 2 次 |
| 从 Chrome 导入 | 2-3 次，必须经过配置确认 |

### 16.3 风险控制

- 高风险操作不可从隐藏入口直接落库。
- 批量操作必须显示影响数量。
- AI 结构治理必须可审阅。
- 清空/覆盖类操作必须双确认。

## 17. 下一步建议

建议按以下顺序推进：

1. 先画信息架构图和新的左侧栏结构。
2. 改 Header 和 MainPageHeader，减少主页按钮噪音。
3. 新增“整理工作台”和“健康维护”两个聚合页。
4. 把现有页面迁移到聚合页入口，不急着改内部逻辑。
5. 统一批量任务页面模板。
6. 统一危险确认组件。
7. 最后再优化视觉细节。

这条路径的好处是：先解决用户迷路和信息过载，不需要一开始重写核心业务逻辑。
